# TTrades Daily Research Loop

This file defines the morning/evening automation contract for turning TTrades concepts into a daily research backlog. The goal is not a digest. The goal is a professional-trader workflow that gathers market/economic context, compares the day against TTrades concepts, and improves the knowledge base after each run.

## Durable Artifacts

- `results/daily_research_backlog.json`: active daily setup backlog. Create it if missing.
- `results/daily_research_history.jsonl`: append-only record of morning and evening runs. Create it if missing.
- `results/research_backlog.json`: corpus/concept backlog generated by broader research workflows.
- `results/workflow_status.json`: current model/data-loop status and next action.
- `data/ttrades_concept_backlog_seed.json`: seed concept/data-needs backlog for daily setup research.
- `data/ttrades_daily_research_backlog.schema.json`: expected backlog record shape.
- `data/ttfm_market_context_map.json`: mapping between teacher screenshots and replayable market context.
- `knowledge/second_brain`: durable notes, playbooks, journal reviews, case studies, and failure modes.
- `knowledge/ttfm_video_corpus/*embedding*_index.json`: teacher/video/screenshot retrieval sources.

## Morning Automation

The morning run should create or update the daily plan:

1. Gather current market and economic context for the watched instruments and sessions.
2. Read `results/workflow_status.json`, `results/research_backlog.json`, `data/ttrades_concept_backlog_seed.json`, and the current `results/daily_research_backlog.json` if it exists.
3. Select a small watchlist of candidate setups using TTrades concepts:
   - daily bias
   - liquidity sweep
   - displacement
   - CISD
   - protected swing
   - point of interest
   - fair value gap / inversion fair value gap
   - breaker block
   - candle 2 / candle 3 / candle 4
   - MMXM or daily profile when the evidence supports it
4. Pull historical analogs from teacher videos, screenshots, transcripts, and embedding indexes.
5. Update `results/daily_research_backlog.json` with watch candidates, evidence, missing data, and explicit invalidation conditions.
6. Append a compact run summary to `results/daily_research_history.jsonl`.

Morning output should answer:
- What setups are worth watching?
- What context would make them valid?
- What would disqualify them?
- Which historical TTrades examples are most relevant?
- What evidence is missing?

## Evening Automation

The evening run should turn the day into learning data:

1. Re-open the morning backlog, current-day journal, screenshots, TradingView captures, and inbox notes.
2. For each morning candidate, classify the result as `validated_setup`, `failed_setup`, `not_ttrades_model`, `ambiguous`, or `needs_more_data`.
3. Compare the result against TTrades concept requirements and historical analogs.
4. Record embedding false positives and useful analogs. Embeddings are retrieval evidence, not verdicts.
5. Update `results/daily_research_backlog.json` and append the review to `results/daily_research_history.jsonl`.
6. Update `knowledge/second_brain` only when the run creates reusable knowledge:
   - a new playbook rule
   - a recurring failure mode
   - a case-study insight
   - an embedding retrieval lesson
   - a market-context mapping correction

Evening output should answer:
- What actually played out?
- Was the setup valid under the TTrades model?
- Which evidence supported or contradicted the thesis?
- What should be watched or researched next?

## Evidence Standards

Use these evidence grades:

- `strong`: chart evidence, TTrades concept requirements, and historical analogs agree.
- `mixed`: partial support or meaningful timeframe conflict.
- `weak`: mostly narrative, hindsight, or embedding-only.
- `insufficient`: key market data, screenshot, timestamp, or teacher context is missing.

Do not promote a claim to reusable knowledge unless evidence is `strong` or the failure mode is clear.

## Backlog Discipline

Every active item should have:

- a concrete symbol/session/timeframe stack
- the TTrades concepts being tested
- source paths or URLs for evidence
- historical analogs or an explicit note that analogs are missing
- invalidation criteria
- next data need

Close items aggressively when they are no longer useful. Keep unresolved items only when they identify a specific data gap or research question.
